Read left to right, top to bottom. Green is your laptop and the local stack, blue is GitHub, and orange is the real hosted project and your phone. Dashed pink arrows are steps only you, the human, ever take.

Your laptop · local

M1 Mac

You + AI agents

  • Agents open PRs, never merge, never run :hosted (except logs:hosted)

mise run setup

One command on a fresh Mac. Installs Node 24, pnpm, Deno 2, Zulu 17, Colima and the Android SDK, then starts local and runs db:reset. Safe to re-run.

Local Supabase stack local

  • Supabase CLI v3 in Colima, default ports
  • Seed: agent@wearai.test, onboarded
  • Image budget cap 1000, fake image provider
  • Flash and SAM make real free calls

Metro: dev / dev:hosted

Serves JS to the development build. APP_ENV picks local (default) or hosted.

secrets:hosted human only

Prompts for the Flash, Roboflow and Nano Banana keys and sets them on hosted. No copy is kept anywhere.

apk:hosted human only

Builds the release APK from clean main, signs it with ~/.config/wearai/release.jks and runs adb install.

GitHub

public repo, free runners

Dependabot monthly

One grouped PR per ecosystem (npm, deno, actions). Expo SDK packages are ignored. Never auto-merges.

Pull request

Every change, even a typo fix. A destructive migration says so in the title.

ci job automatic

Runs mise run test and nothing else: check, expo export, expo install --check and the pgTAP image-budget test. No secrets.

main

  • Ruleset: PR + green ci, 0 approvals, no bypass
  • Squash merge only. You merge
  • No git hooks

deploy workflow on merge

Runs only when supabase/** changed: restore if paused → db push → functions deploy. Never sets secrets.

keep-alive daily cron

One cheap read so the Free project doesn't pause after 7 idle days.

Tests: deliberately minimal

You're the only User, so tests guard only against an app that won't build and an image budget that fails open. No test ever calls a real model.

Automated (mise run test, also in CI)
  • check: tsc --noEmit, deno check, expo lint, deno lint, prettier --check
  • expo export --platform android: the app bundles
  • expo install --check: packages match the Expo SDK
  • One pgTAP test: the image budget stops at its cap
Not automated, on purpose
  • RLS and Storage leak tests: write them before a second person signs in
  • Edge Function tests (none yet; check still typechecks them)
  • Android end-to-end tests: installing on the phone is the smoke test
  • Product logic (Feed and Style Me limits, Stylist rotation, UI)
Phone checklist for a new hosted APK
  1. It launches, with no LOCAL badge.
  2. Google sign-in works.
  3. The Wardrobe loads.
  4. One Upload reaches in_review (Flash and SAM are free).
  5. The existing Feed loads. Don't press Generate Feed or Style Me; they spend paid images.

The 12 decisions

In the order they were made. Each title links to its closed ticket, which holds the full reasoning. A note under a card marks where a later decision changed it.

1 · researchphone builds

How do we get an Expo Android build onto the OnePlus 7T for $0?

  • A development build, not Expo Go (Expo Go can't do native Google Sign-In)
  • The laptop builds with expo run:android
  • EAS Free is only a fallback
Later: the hosted APK is built on the laptop, not in CI, and the keystore never goes into GitHub (decision 10).
2 · researchtests

Which free test tools fit each layer of WearAI?

  • DB: pgTAP via supabase test db
  • Functions: deno test with fetch stubbed
  • App: typecheck, expo lint, expo export, expo install --check
  • Maestro end-to-end is free but not worth it yet
Later: trimmed to the minimal set in decision 7.
3 · researchSupabase

What do Supabase's local stack and Free plan give us for dev and deploys?

  • CLI v3 targets local by default; hosted needs --remote --yes
  • Free: 2 projects, pause after ~7 idle days, restorable. Branching is paid
  • CI deploys need only an access token and the project ref
4environments

Which environments exist, and what does each one call?

  • Exactly two: local and hosted
  • Nano Banana runs only on hosted; local uses a fake
  • Google Cloud is split: wearai-free (no billing) and wearai-images
  • Commands target local unless named :hosted
5toolchain

What are the repo layout and toolchain?

  • One package at the root, supabase/ beside it, no workspaces
  • mise.toml pins Node 24, pnpm, Deno 2, Zulu 17
  • Supabase CLI is a pnpm devDependency; Colima replaces Docker Desktop
  • Strict TypeScript, expo lint + deno lint, Prettier
6commands

What is the single command surface?

  • mise tasks named area:verb
  • setup is idempotent and never uninstalls
  • A ▸ local / ▸ hosted banner before anything touches Supabase
  • AGENTS.md gets a short Commands section
7tests

What do the minimal tests cover, and how are model calls kept out?

  • check, expo export, expo install --check
  • One pgTAP test that the image budget stops at its cap
  • No RLS, function or end-to-end tests; no test calls a model
  • A five-step phone checklist for hosted APKs
8secrets

Where do secrets live, and how do they flow in a public repo?

  • Public values are committed in .env.local / .env.hosted
  • Local function keys in a gitignored supabase/functions/.env
  • Hosted secrets only via secrets:hosted; the paid key never touches disk or CI
  • Hosted sign-ups close after your first sign-in
9CI

What runs in CI on a PR, and what protects main?

  • One ci job: mise run test, every PR and push, no secrets
  • Ruleset: PR + green ci, 0 approvals, no bypass
  • Squash-only merges; agents never merge; no git hooks
10deploys

How do changes reach hosted Supabase and the phone?

  • Backend deploys automatically on merges that touch supabase/
  • A daily keep-alive stops the project pausing
  • Human-only apk:hosted builds on the laptop; keystore stays there
  • Two variants side by side; no OTA; rollback = revert on main
11dependencies

How are dependencies kept current, and do updates auto-merge?

  • Dependabot from one committed file: npm, deno.json, Actions
  • Monthly, one minor/patch group per ecosystem; majors separate
  • Expo SDK upgrades and mise.toml bumps are done by hand
  • No auto-merge; alerts and security fixes on
12seed data

How does hosted get its reference data and first Wardrobe?

  • Categories, Stylists and the budget row (cap 30) go in a migration
  • seed.sql is local only: cap 1000 and agent@wearai.test
  • Stylist sample images are app assets, made free in the Gemini app
  • Your hosted Wardrobe comes only from using the app

Still to confirm when it's built

  • Whether db push works with only the scoped access token, or also needs the DB password.
  • Exactly how hosted sign-ups get closed: a hosted-only config override or the Management API.
  • Whether Google sign-in works against local on the phone. If not, add a __DEV__-only email sign-in.
  • Whether Dependabot's Deno support reads one deno.json per function, and supports the pinned pnpm.
  • Whether turning on billing for wearai-images needs a $5 prepayment.

Ruled out of scope

iOS · Play Store pipelines · production monitoring and alerting · onboarding a second developer · per-PR preview environments · performance and load testing · any paid plan or add-on · RLS and Storage leak tests until a second person signs in.
