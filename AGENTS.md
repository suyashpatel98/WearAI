## Commands

Run every command as `mise run <task>`. `mise tasks` lists them all with descriptions; that list is the source of truth. Never add `package.json` scripts. Run the Supabase CLI as `pnpm supabase …`, never a global `supabase`.

The four to know: `setup`, `check`, `test`, `db:reset`.

- **Never run a `:hosted` task except `logs:hosted`.** Never set `SUPABASE_YES`, and never pass `--remote` or `--yes` to the Supabase CLI yourself. The developer changes hosted, not agents.
- **Never print, commit or paste the contents of `supabase/functions/.env`.**
- **Open PRs, but never merge them.** The developer merges.
- **A migration that drops or rewrites data says so in the PR title.**
- How to test: run `check` while iterating, and `test` before opening a PR. After changing a migration or a policy, run `db:reset`, then `test:db`.
- New migrations come from `mise run db:new <name>`. `db:reset` is the only way to apply them locally, and it also regenerates the DB types. Commit the regenerated `supabase/functions/_shared/database.types.ts`.
- Sign in on local as `agent@wearai.test` with the password `wearai-local-only` (local only). OTP mail goes to Mailpit at http://127.0.0.1:54324.

## Expo

The app is an Expo SDK 58 app using Expo Router, with routes in `src/app/`. Expo changes between SDK releases, so check `https://docs.expo.dev/versions/v58.0.0/` rather than relying on memory.

- Add packages with `pnpm expo install <package>`, so their versions match the SDK.
- `android/` is generated by `expo prebuild` and gitignored. Configure native behaviour in `app.config.ts` and config plugins, never by editing `android/`.
- No EAS Build, EAS Update or `expo-updates`. Builds happen on the laptop (`android`, `apk:hosted`).
